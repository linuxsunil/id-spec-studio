# ID Review Standard

The rubric all Goldfish reviewers apply when auditing a course design spec.
Grounded in evidence-based instructional design — Merrill, Clark, Gagné, Bloom, Sweller, Keller.

---

## Standard 1: Objective Quality

**What good looks like:**
- Each objective uses an observable, measurable verb (Bloom's taxonomy, appropriate level)
- Objectives describe learner behavior, not content coverage
- Objectives are written at the right Bloom's level for the domain and audience
- Each objective can be directly assessed

**Red flags:**
- Vague verbs: understand, appreciate, know, be aware of, learn about
- Objectives written as instructor actions ("cover," "present," "introduce")
- No clear assessment link
- Bloom's level mismatch (e.g., Remember-level objective for a decision-making task)

---

## Standard 2: Alignment (Objectives → Content → Assessment)

**What good looks like:**
- Every objective maps to at least one learning activity
- Every objective maps to at least one assessment item
- Content directly serves the objectives — no orphaned content
- Assessment measures the stated objective, not a proxy

**Red flags:**
- Objectives with no corresponding activity
- Assessments that test recall when the objective targets application or analysis
- Content sections that have no linked objective
- Module sequence breaks prerequisite order

---

## Standard 3: Audience Specification

**What good looks like:**
- Audience description is concrete: role, experience level, prior knowledge, context of use
- Prerequisites are explicitly stated and realistic
- Motivation or resistance factors are acknowledged
- Delivery context is considered (time pressure, device, location)

**Red flags:**
- Vague audience: "all employees," "managers," "anyone interested"
- No prior knowledge stated
- No context for when/where learning happens
- Assumed motivation without evidence

---

## Standard 4: Theory Selection and Application (Merrill + Clark + Gagné)

**What good looks like:**
- At least one primary theory is selected and justified for the domain
- Theory selection matches task type (concept/procedure/principle/problem)
- Merrill's First Principles present: activation, demonstration, application, integration
- Gagné's Events of Instruction addressed: gain attention, state objective, recall prior, present stimulus, guide learning, elicit performance, provide feedback, assess, enhance retention/transfer
- Cognitive load managed: intrinsic load matched to audience; extraneous load minimized
- Clark's Evidence-Based Principles applied where relevant: worked examples, practice, feedback

**Red flags:**
- No theory justification — just a list of activities
- Theory selected but not reflected in any design decision
- Cognitive overload risk: too many new concepts introduced at once
- No activation of prior knowledge
- No guided practice before independent assessment

---

## Standard 5: Assessment Design

**What good looks like:**
- Assessment type matches objective level (Bloom's alignment)
- At least one formative checkpoint per module
- Scenario-based or application-level items for skill objectives
- Feedback is instructional, not just correct/incorrect
- Assessment conditions match transfer conditions

**Red flags:**
- Only recall-level items (MCQ with no application)
- No formative assessment
- Generic feedback ("Correct!" or "Try again")
- Assessment disconnected from real-world context stated in audience description

---

## Standard 6: Instructional Strategy

**What good looks like:**
- Strategy matches content type: concepts need examples + non-examples; procedures need steps + practice; principles need cases; problems need scenarios
- Learning sequence is logical: simple to complex, known to unknown
- Interactivity is purposeful, not decorative
- Each interaction requires a decision or judgment, not just a click

**Red flags:**
- One-size-fits-all strategy (e.g., all content delivered as text + MCQ)
- Interactivity that doesn't require thinking
- No examples or worked examples for complex skills
- No variation in practice type across modules

---

## Standard 7: Motivation Design (ARCS)

**What good looks like:**
- Attention: opening creates relevance or poses a problem
- Relevance: learners can see direct application to their role
- Confidence: success criteria are clear; early wins are designed in
- Satisfaction: learners experience meaningful accomplishment

**Red flags:**
- No motivational hook at the start
- Relevance assumed, not designed
- No confidence-building sequence for difficult content
- Course ends without a sense of completion or application

---

## Standard 8: Practicality and Buildability

**What good looks like:**
- Scope matches stated duration and tool constraints
- All specified media types are achievable in the stated authoring tool
- SME availability is accounted for
- No features that require capabilities not stated in the brief

**Red flags:**
- Ambitious scope for stated timeline
- Interaction types not supported by stated delivery tool
- Video or simulation specified without production resource
- No phasing or prioritization if scope is large

---

## Severity Levels

| Level | Symbol | Meaning |
|---|---|---|
| Blocker | 🔴 | The spec cannot go to build in this state. Specific gap or misalignment identified. |
| Major | 🟡 | Significant weakness that will likely produce a poor learning experience if not addressed. |
| Nit | 🟢 | Minor improvement that would strengthen the design. Non-blocking. |
