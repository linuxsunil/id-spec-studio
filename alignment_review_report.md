## Findings

### Blockers
[Finding ID: alignment-1-1] Section 3 (Terminal Objective, lines 44-46); Section 7 (terminal row, line 145); Section 6 (Observed measure, line 133) — The terminal objective has three measurable criteria: response within 30 seconds, value statement before any price or discount, and the three-part structure. The only assessment named is the manager checklist, with a pass rule of "attempts the three-part response before any discount." That rule checks order only. It does not check the 30-second limit, the presence of all three parts, or the value statement. The checklist itself is referenced as a job aid but is not specified anywhere in the spec, and the spec does not say how the 30-second limit is timed or observed. Section 4 (line 65) also states a 30-second rule as procedural information that no course item checks. The terminal objective, the course's headline outcome, therefore has no assessment that measures the stated objective. Blocker because the spec cannot show the chain Objective -> Assessment is complete for the terminal objective. Recommendation: Specify the observation checklist criteria in the spec (one line per criterion: acknowledgment, pivot, qualifying question, value before price, under 30 seconds, and how the time is measured). Set the pass rule to cover every terminal criterion, or narrow the terminal objective to what is measured. Either way, state the decision in Section 3 and Section 7.

### Major
[Finding ID: alignment-1-2] Section 3 (objective 1, line 35); Section 5 (Module 2 row, line 102-103); Section 6 (Module 2, line 124) — Objective 1 requires recall of the approved differentiator for each of the five objections. No section of the spec presents those differentiators. Module 2 covers the three-part structure and a reference card, and the recall items are not described. The differentiators are owned by the sales director (Section 10, line 188), and no content is listed for them. Recall items therefore test content the spec never teaches. Recommendation: Add a content table listing the differentiator for each objection, its source (battle card or SME-approved script), and the module where it is presented. Mark it as an SME dependency for alignment purposes.

[Finding ID: alignment-1-3] Section 3 (objective 2, line 36); Section 7 (line 142); Section 5 (Module 1, line 101); Section 8 (line 164) — Objective 2 requires learners to explain the value-first case "citing the cost of discounting in their own terms." The assessment is a scenario choice that selects the explanation matching the deal math. That measures recognition of an explanation, not the learner's own citation of cost. Module 1 uses a worked numeric example, not the learner's numbers. Section 8 says reps will see the cost "in their own numbers," but Section 12 (line 217) states that the cost of the gap is not quantified. The objective's condition is not met by the design. Recommendation: Either reword objective 2 to match the design (for example, "explain the value-first case using the deal math from a worked example"), or add an item in which the learner calculates or states the cost of a discount using their own input values. Remove the "own numbers" claim from Section 8 unless the design provides them.

[Finding ID: alignment-1-4] Section 6 (Module 3 row, line 125); Section 7 (formative checkpoints, lines 149-153; objective 4 row, line 144) — Module 3 lists objective 4 as covered, but its key activity is the worked/partly completed/independent branch sequence (line 125), which has no analysis or error-spotting task. Objective 4 is assessed only in the Module 5 summative item (line 144). The formative checkpoint list (lines 150-153) contains no objective 4 checkpoint. Learners therefore meet an Analyze-level task for the first time in the summative. Recommendation: Add a formative error-spotting item (for example, one transcript line in Module 3 or 4) with feedback naming the skipped step, and correct the Module 3 coverage entry if the activity does not include it.

[Finding ID: alignment-1-5] Section 7 (line 141, objective 1 "Formative and summative"; line 143, objective 3 summative in Module 5; line 155, summative definition); Section 6 (Module 5 row, line 127) — The summative assessment is defined as "the Module 5 branching items and error-spotting item, combined" (line 155). That covers objectives 3 and 4 only. Section 7 nevertheless lists objective 1 as summative (line 141), and objective 2 has no summative item. The Module 5 row (line 127) lists objectives 4 and terminal, but Section 7 (line 143) places the objective 3 branching items in Module 5. The 80% pass threshold therefore does not represent objectives 1 and 2, and it cannot be verified which objectives it covers. Recommendation: Add an objective-to-summative-item map. Either include objective 1 in the summative set or remove the summative label from its row. Add objective 3 to the Module 5 row. State whether objective 2 has a summative item or is formative only by design.

[Finding ID: alignment-1-6] Section 3 (objective 1, line 35, "without notes"); Section 5 (line 102, reference card kept on screen); Section 6 (Module 2, line 124); Section 7 (line 141) — Objective 1 states the learner recalls differentiators without notes. The spec also keeps a reference card on screen as a job aid, and the matching item's conditions are not stated. If the card is visible during the matching item, the assessment does not match the stated condition (Standard 5: assessment conditions must match transfer conditions). Recommendation: State whether the matching item is closed-book (card hidden or unavailable). If it is open-book, change the objective wording to remove "without notes."

### Nits
[Finding ID: alignment-1-7] Section 3 (Terminal Objective, lines 44-46) — The terminal objective has no stated Bloom's level. Its behavior is performance under time pressure, which corresponds to Apply. Recommendation: Add "Bloom's level: Apply (performance)" beside the terminal objective so Standard 1 is met and the level can be compared with objective 3.

[Finding ID: alignment-1-8] Section 3 (Bloom's note, line 40) — The note says "Objective 3 is the terminal behavior," but the Terminal Objective section (lines 44-46) adds a 30-second limit and value-first condition that objective 3 does not state. The two are not the same objective, so the chain is ambiguous. Recommendation: Change the note to state that objective 3 is the course-level component of the terminal objective, and list which terminal criteria objective 3 does not cover (the 30-second limit).

## Summary
The chains from objectives 3 and 4 to their scenario and transcript items are sound, and Module 3 and 4 formative checks are in place for objective 3. The design breaks at the terminal objective, which has no assessment that measures its stated criteria, and at the summative map, which does not say which objectives it covers. Objective 1 has no content listed in the spec, and objective 2 is assessed by recognition rather than the citation its wording requires.
